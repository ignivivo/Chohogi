# 연속성 작업 봉투

긴 작업에서 결론·근거·다음 경계를 압축해 컨텍스트 단절과 중복 실행을 막는다. 이는
별도 하네스가 아니라 trunk가 관리하는 최소 기록이다.

## 만들 때

- 두 개 이상의 실행 세포·검토 경계가 있는 substantial 작업
- 여러 차례에 걸친 구현, 또는 컨텍스트 단절 위험

짧은 직접 처리에는 만들지 않는다. 비밀값, 원문 개인 정보, 긴 대화 전문은 넣지 않는다.

## 최소 형식

```text
task: <식별자와 목표>
flow / allocation: <flow> / <direct|sequential|scoped-delegation>
accepted constraints: <수용 조건·제외 범위>
ownership: <역할: 파일 또는 읽기 전용 경계>
authority: <read|specified-write|shared-contract-write|external-side-effect|global-asset-change>
baseline: <기준 revision·공유 계약·테스트 환경>
decisions: <결정과 근거>
decision authority: <agent recommendation | user/authorized-owner resolution | pending report>
evidence: <명령·결과·관측>
handoff: <수신자·고정 diff 또는 phloem return 여부>
next: <완료 항목 또는 다음 하나의 경계>
```

주 에이전트만 봉투를 갱신하고, 각 역할은 자신의 근거만 보고한다. Git과 프로젝트
work log가 장기 역사이며 이 봉투는 현재 작업을 잇는 압축본일 뿐이다. material work가
`execution-record.py`를 사용한다면, 다음 실행자는 먼저
`handoff --work-id <id>`의 기계적 projection을 읽는다. 사람·모델이 쓰는 봉투에는 그
projection으로 표현할 수 없는 배경·판단만 추가하며, 같은 현재 상태를 두 파일에
복사해 별도로 유지하지 않는다.

## 지속 문서의 위치와 분량

적용: 긴 작업에서 문서·결정·계획·인수인계를 만들거나 통합·분할할 때. 문서 역할·권위·참조 방향은 `document-lifecycle.md` 계약을 따른다.
소유자: 주 에이전트가 프로젝트의 기존 문서 책임과 권한 안에서 관리한다.
단순 답변에는 새 문서를 요구하지 않으며, 모든 프로젝트에 같은 폴더를 강제하지 않는다.

입력은 기존 진입 문서, 관련 결정 본문과 상태, 실제 소비자, 중복·참조 목록이다.
문서 생성보다 먼저 아래 기준으로 기존 문서의 절을 갱신할 수 있는지 판단한다.

- 같은 질문·독자·책임·변경 주기라면 통합한다. 피드백마다 새 PRD·PD·handoff를 만들지 않는다.
- 독자·소유권·권한·수명 또는 원문 증거 보존 의무가 다르면 분리한다. 파일 수나 줄 수는 단독 기준이 아니다.
- 현재 상태, 채택된 계약, 제안, 결정 이유, 원문 증거, 실행 이력을 구별한다. 한 규칙의 소유 문서는 하나이며 나머지는 링크한다. 수정 제안이 채택된 계약을 조용히 덮어쓰면 안 된다.
- 프로젝트가 계획 문서를 쓴다면 활성 실행 소유자는 정확히 하나다. 그 문서는 현재 큐와 완료 조건을 소유하고, 이전 계획·감사·실행 기록은 역사 또는 증거로 표시해 실행 지시로 읽히지 않게 한다. 피드백마다 새 활성 계획을 만들지 말고 현재 소유 문서를 갱신한다.
- 새 파일은 기존 절로 담기 어려운 이유와 소유 역할을 확인하고 기존 진입 문서에 연결한다. 안내만 하는 색인·계획·봉투를 겹쳐 만들지 않는다.
- 실행 기록이 현재 경계와 다음 행동을 이미 담으면 별도 봉투 파일을 복제하지 않는다. 과거 기록은 필요할 때 찾고 모든 작업에 전체 이력 읽기를 요구하지 않는다.
- 통합은 고유 요구·결정 ID·날짜·승인 상태·미해결 충돌·출처를 보존한다. 이동 전후 경로와 살아 있는 참조를 대조한 뒤 중복본을 제거한다. 원문 증거와 과거 이벤트의 해시는 소급 수정하지 않는다.
- 전역 규칙은 전역 소유 저장소에서, 프로젝트 차이는 프로젝트에서 관리한다. 설치본만 고치거나 전역 지침 전문을 프로젝트 문서에 복제하지 않는다.

출력은 기존 진입 문서의 책임 지도, 통합된 본문, 필요한 최소 이동 기록이다.
검증은 살아 있는 링크 확인과 관련 결정의 의미 대조다. 파일 존재·해시·finalize 통과만으로 내용 준수나 향후 에이전트 행동을 보증하지 않는다.
재검토는 같은 규칙이 여러 곳에서 달라지거나, 현재 기준을 찾지 못하거나, 통합으로 서로 다른 독자의 탐색이 어려워질 때 한다.
