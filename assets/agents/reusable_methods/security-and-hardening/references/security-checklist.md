# 보안 검증 보조표

`security-and-hardening`이 실제 보안 변경에 적용될 때만 사용한다. 실제 스캐너 결과와
사람의 위협 모델을 대체하지 않는다.

- 설치 경계와 단일 lockfile을 확인한 뒤 해당 package manager의 audit를 실행한다.
- 새 의존성·lockfile·install script 변경은 함께 검토하고, 강제 자동 수정은 하지 않는다.
- 비밀값은 staged diff와 배포 환경을 분리해 확인한다. 노출이 확인되면 삭제보다 폐기·재발급을 먼저 한다.
- 외부 입력, URL fetch, LLM 출력, 웹훅, 파일은 각각 검증·권한·허용 목록을 가진다.
- 보안 헤더·CORS·인증 경계는 실제 응답 또는 배포 설정으로 확인한다.

실제 SAST·시크릿 탐지·헤더 검사는 provider 또는 CI가 담당한다. 사용할 수 없으면
미실행 사실과 남은 위험을 보고한다.
