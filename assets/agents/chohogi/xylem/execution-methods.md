# 실행 방법

이 문서는 외부 절차 하네스의 좋은 방법을 초호기 내부 xylem으로 흡수한 것이다. 실행
형태를 선택하지 않고, `execution-allocation.md`가 정한 역할에 필요한 방법만 공급한다.

## 계획·구현

1. 수용 조건, 생산자/소비자, 제외 범위를 작업 봉투에 고정한다.
2. 실패 조건이 의미 있는 보호막이면 먼저 명확히 하고 최소 구현을 한다.
3. 기계적 문서 변경처럼 맞지 않는 경우에는 형식적 TDD를 강제하지 않는다.
4. 구현 뒤 직접 영향 범위와 교차 계약을 검증한다.

## 디버깅

관측·재현·가설·판별 증거를 먼저 모은다. 원인 확인 전 여러 파일을 추측 수정하지
않는다. 원인이 확인된 뒤 최소 수정과 해당 회귀 검증으로 Delivery로 이어진다.

## 검토

고위험 계약, 보안, 개인정보, 결제, 또는 다중 소비자 변경만 독립 reviewer를 사용한다.
검토자는 요구사항·변경 diff·검증 증거를 보고 구체적 근거가 있는 finding만 낸다. 작은
기계적 변경에 의례적인 독립 검토를 강제하지 않는다.

## 완료

실제로 실행한 명령·결과·미실행 검증·남은 위험을 사실대로 남긴다. 외부 절차가 요구한
별도 controller, 실행 선택 질문, branch/worktree, commit 방식은 이 방법의 일부가 아니다.
