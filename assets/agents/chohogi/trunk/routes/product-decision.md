# Product-decision route

<!-- chohogi:section=role -->
## 역할

사용자가 정해야 하는 제품·정책·범위 선택을, 사실과 가정을 섞지 않고 결정 가능한
형태로 정리한다. 이 route는 사용자를 대신해 중요한 제품 결정을 확정하지 않는다.

<!-- chohogi:section=entry -->
## 진입 조건

- 결과에 영향을 주는 선택지가 둘 이상이며, 아직 사용자가 선택하지 않았다.
- 요구사항의 빈칸을 임의로 채우면 제품 범위·비용·위험·사용자 경험이 달라진다.
- 사용자가 비교, 기획, 방향 설정, 우선순위 결정을 요청했다.

<!-- chohogi:section=negative-scope -->
## 사용하지 않는 경우

- 요구사항과 수용 조건이 충분히 확정되어 있으면 `delivery`를 선택한다.
- 관측 가능한 실패의 원인이 불명확하면 `debugging`을 선택한다.
- 사실 확인·설명·명확한 저위험 편집은 직접 처리한다.
- 단순한 세부 구현 선택은 가장 작은 안전한 가정을 밝히고 `delivery` 안에서 처리한다.

<!-- chohogi:section=input -->
## 입력

- 사용자의 목표와 이미 확정된 제약
- 결정권자와 결정이 필요한 시점
- 확인된 사실, 미확정 가정, 비교 가능한 선택지

<!-- chohogi:section=method -->
## 절차

1. 이미 확정된 사항과 실제로 열린 결정을 분리한다.
2. 결정에 필요한 사실을 수집하고, 모르는 것은 모른다고 표시한다.
3. 선택지별 이점·비용·위험·되돌릴 수 있는 정도를 같은 기준으로 비교한다.
4. 사용자가 요청했거나 중요한 맥락이 부족할 때만 제한된 질문 또는 브레인스토밍을
   사용한다. 질문을 늘리는 것 자체를 목표로 삼지 않는다.
5. 추천안과 추천 근거를 제시하되, 사용자의 결정이 필요한 지점은 명시한다.
6. 결정되면 `delivery`가 사용할 수용 조건과 보류 사항을 남긴다.

<!-- chohogi:section=optional-capabilities -->
## 선택적 능력

- 비교 대상의 최신성·정확성이 중요하면 관련 1차 자료를 조사한다.
- 사용자가 설계를 강하게 검토해 달라고 요청할 때만 `grill-me`를 사용한다.
- 독립적인 위험 검토가 필요한 고영향 결정에서만 별도 검토를 요청한다.

<!-- chohogi:section=exit -->
## 산출물과 종료 조건

산출물은 문제 정의, 확정 사실, 선택지와 trade-off, 추천안, 사용자 결정 필요 여부,
결정 뒤의 수용 조건이다. 사용자가 결정을 내렸거나, 결정을 내리기 위해 필요한
정보·질문이 명확해졌을 때 종료한다.

## 다음 분기

  전환한다.

  `homeostasis`를 선택한다.
