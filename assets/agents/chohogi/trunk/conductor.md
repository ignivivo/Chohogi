# Conductor — 초호기 작업 분류기

Conductor는 초호기의 일상 진입점이다. 이 문서는 작업을 수행하는 두 번째 하네스가 아니라, 현재 작업에 맞는 제어 흐름을 정확히 하나 고르는 분류기다.

## 직접 처리

짧은 질문, 읽기 전용 확인, 범위가 명확한 저위험 편집은 바로 수행한다. 별도 작업 패킷이나 스킬 묶음을 만들지 않는다. 전역 자산 생성·정책·역할·모델·스킬 수명 변경처럼 고영향 지속 변경을 요청한 작업은, 증거가 부족하다는 이유만으로 직접 처리로 낮추지 않는다.

## 보류·무변경 (`defer`)

작업이 substantial하더라도 현재 증거·전제가 부족해 아래 어느 흐름의 엄격한 진입 조건도 충족하지 못하면 억지로 흐름을 고르지 않는다. 특히 전역 자산 생성·정책 변경을 요청했지만 확인된 실패·원인·효과 근거가 없는 경우에는 직접 처리로 낮추지 않고 `defer`를 고른다. 이때 `defer` 결과로 증거 공백, 지금 수행하지 않는 변경, 재진입에 필요한 관측·결정·권한을 명시한다. `defer`는 route·branch·상시 스킬이 아니며, 도구 호출이나 지속 변경을 하지 않는다.

## substantial 작업

작업의 범위·생산자/소비자·성공 조건·위험이 둘 이상 얽히면 짧은 작업 봉투를 남긴다. 아래 흐름의 엄격한 진입 조건이 하나 이상 맞을 때만 그중 하나를 선택하며, 맞는 조건이 없으면 `defer`로 끝낸다.

| 흐름 | 선택 조건 | 필수 산출물 |
| --- | --- | --- |
| `product-decision` | 사용자 선택 또는 제품 정책의 중요한 빈칸이 결과를 바꾼다 | 선택지·결정·근거 |
| `delivery` | 요구사항과 성공 조건이 충분히 정해졌다 | 구현·검증 증거 |
| `debugging` | 관찰 가능한 실패가 있고 원인이 아직 불명이다 | 재현·관측 근거·원인 상태·제안 또는 권한 있는 수정 검증 |
| `learning` | 원인이 확인됐고 재발 방지 자산 후보가 있다 | 최소 예방 자산 또는 승격 보류 근거 |
| `homeostasis` | 초호기 정책·역할·모델·스킬 수명·설치/발견 자체를 바꿔야 한다 | 변경 계약·설치 검증 |

`product-decision`, `delivery`, `debugging`을 선택한 뒤에는 `routes/<flow>.md`와
`execution-allocation.md`를 읽는다. route는 현재 작업의 절차이고, 실행 배정 계약은
초호기 내부에서 직접·순차·제한적 위임 중 하나와 역할 소유권을 정한다. 이 문서들은
별도 controller·하네스·상시 스킬이 아니다. `learning`과 `homeostasis`는 branch skill이므로 각각의 엄격한 진입 조건을 만족할 때만 선택한다.

현재 흐름의 산출물 또는 증거가 생기기 전에는 다른 흐름으로 옮기지 않는다. 기술·도메인 스킬과 도구는 흐름과 실행 형태를 정한 뒤에만 필요한 것 하나씩 고른다. 이들은 범위, 위임, 완료를 스스로 결정하지 않는다. 외부 능력이 필요한지와 흡수된 방법론의 경계는 `capability-selection.md`를 따른다. 실행 방법이 필요하면 `xylem/execution-methods.md`를 읽고, 긴 작업은 `context-packet.md`로 현재 상태만 압축한다.

## 가지 호출

- 확인된 실패의 예방은 `$learning`을 호출한다. 결함마다 스킬을 만들지 말고 테스트·타입·계약·린트·프로젝트 규칙 중 가장 작은 방식을 우선한다.
- 초호기 전체의 불균형은 `$homeostasis`를 호출한다. 보통의 제품 코드 변경에는 호출하지 않는다.

## 비용과 역할

개인 런타임의 기본 모델·인증·플러그인 설정은 초호기의 설치 대상이 아니다. 사용 가능한 모델 중 증거 위험에 맞는 가장 저렴한 선택을 쓴다. 탐색은 저비용, 알려진 범위 구현은 저비용 구현 모델, 독립 고위험 검토만 고비용 검토 모델을 사용한다. 실제 런타임이 그 모델이나 에이전트 역할을 제공하지 않으면 현재 표면의 더 저렴한 대체로 진행한다.

병렬 위임은 독립적이고 경계가 명확한 경우만 하며, 주 에이전트가 통합 책임을 가진다. 실행 방식 자체는 사용자 선택지가 아니다. 제품·권한·비가역 영향·승인되지 않은 비용처럼 결과를 바꾸는 결정만 사용자에게 묻는다.
