# Conductor — 초호기 작업 분류기

Conductor는 초호기의 일상 진입점이다. 이 문서는 작업을 수행하는 두 번째 하네스가 아니라,
현재 작업에 맞는 제어 흐름을 정확히 하나 고르는 분류기다.

## 직접 처리

짧은 질문, 읽기 전용 확인, 범위가 명확한 저위험 편집은 바로 수행한다. 전역 자산 생성·정책·역할·모델·스킬 수명 변경처럼 고영향 지속 변경을 요청한 작업은 증거가 부족하다는 이유만으로 직접 처리로 낮추지 않는다.

## 보류·무변경 (`defer`)

<!-- chohogi:defer=no-flow-no-write -->
작업이 substantial하더라도 현재 증거·전제가 아래 일상 흐름의 엄격한 진입 조건을 충족하지 못하면 `defer`를 고른다. `defer`에서는 지속 변경을 하지 않고 증거 공백, 지금 수행하지 않는 변경, 재진입 조건을 명시한다.

## 일상 흐름

substantial 작업에서는 아래 셋 중 정확히 하나만 고른다.

| 일상 흐름 | 선택 조건 | 필수 산출물 |
| --- | --- | --- |
| `product-decision` | 사용자 선택 또는 제품 정책의 중요한 빈칸이 결과를 바꾼다 | 선택지·결정·근거 |
| `delivery` | 요구사항과 성공 조건이 충분히 정해졌다 | 구현·검증 증거 |
| `debugging` | 관찰 가능한 실패가 있고 원인이 아직 불명이다 | 재현·관측 근거·원인 상태·제안 또는 권한 있는 수정 검증 |

선택 뒤에는 `routes/<flow>.md`와 `execution-allocation.md`를 읽는다. 상태 전이와 handoff는 `state-transition.md`를, 읽기·지정 변경·전역 자산 변경·외부 부작용의 권한은 `authority-lattice.md`를 따른다.

## 유지 과정

`learning`과 `homeostasis`는 일상 흐름과 경쟁하는 route가 아니다.

- `learning`: 종료된 Delivery 또는 Debugging에서 원인·예방 검증이 확인된 뒤에만 `vascular-bundle/phloem-feedback.md`의 정제된 return contract를 받아 최소 예방과 귀속지를 결정한다.
- `homeostasis`: 초호기의 conductor, 역할·모델 정책, skill 수명, 설치·발견 또는 전역 자산 경계 자체를 바꾸는 요청·증거가 있을 때만 별도로 진입한다.

현재 흐름의 산출물 또는 증거가 생기기 전에는 다른 일상 흐름으로 옮기지 않는다. 기술·도메인 스킬과 도구는 흐름과 실행 형태를 정한 뒤에만 필요한 것 하나씩 고른다. 이들은 범위, 위임, 완료를 스스로 결정하지 않는다. 외부 능력의 경계는 `capability-selection.md`, 외부 skill의 이식·외부 유지·leaf·폐기는 Homeostasis의 `skill-adoption.md`, 실행 방법은 `leaf-methods.md`, 긴 작업의 압축은 `context-packet.md`를 따른다.

## 비용과 역할

실행 배정은 사용자 메뉴가 아니다. 초호기가 직접·순차·제한적 위임 중 하나와 역할 소유권을 정하고, 주 에이전트가 통합 책임을 가진다. 사용 가능한 모델 중 증거 위험에 맞는 가장 저렴한 선택을 쓰며, escalation 이유·재시도 상한·fallback을 작업 봉투에 남긴다. 제품 정책, 외부 권한, 비가역 영향, 승인되지 않은 비용처럼 결과를 바꾸는 결정만 사용자에게 묻는다.
